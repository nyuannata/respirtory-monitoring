--------------------------------------------------------------------------------
  GAMBARAN UMUM SISTEM
--------------------------------------------------------------------------------

  Alur Data Sistem:
  [ESP32 + Sensor] --> MQTT (health/monitoring/data)
       --> [Python live_prediksi.py]
       --> MQTT (health/monitoring/hasil)
       --> [Dashboard Web (React + TypeScript)]

  Komponen Utama:
  - Sensor Suhu     : DS18B20 (pin GPIO 4)
  - Sensor BPM      : MAX30102 (via I2C Multiplexer TCA9548A, Channel 0)
  - Sensor RR       : MPU6050 Akselerometer (via TCA9548A, Channel 1)
  - Broker MQTT     : HiveMQ Cloud (TLS/SSL Port 8883 / WSS Port 8884)
  - Model AI        : Random Forest Classifier (scikit-learn, 100 estimators)
  - Dataset         : 900 baris sintetis (300 Normal, 300 Peringatan, 300 Bahaya)
  - Frontend        : React + TypeScript + Vite + Recharts + Framer Motion

  [PENINGKATAN #1] -- Gelombang Pernapasan Akurat Sesuai Sensor
  ============================================================
  File     : src/App.tsx (komponen BreathingWaveform)
  Status   : DIPERBARUI

  Masalah Lama:
    Kecepatan animasi gelombang tidak berkorelasi matematis
    dengan nilai RR dari sensor. Formula lama memakai incremen
    arbitrari: time += 0.015 + (respRate * 0.0005)

  Solusi Baru (performance.now() + rumus fisika):
    timeAtX = elapsedSeconds - (canvasWidth - x) / SCROLL_PX_PER_SEC
    phase   = timeAtX * (respRate / 60) * 2 * PI
    y       = sin(phase) * amplitudo

  Korelasi Nilai Sensor vs Kecepatan Gelombang:
    RR = 12 BrPM  -> 1 siklus gelombang setiap 5.00 detik
    RR = 16 BrPM  -> 1 siklus gelombang setiap 3.75 detik
    RR = 24 BrPM  -> 1 siklus gelombang setiap 2.50 detik
    RR = 32 BrPM  -> 1 siklus gelombang setiap 1.88 detik

  Tambahan:
    - Harmonik sekunder ditambahkan untuk tampilan lebih natural
    - useRef untuk startTime agar animasi mulus saat RR berubah

  ============================================================
  [PENINGKATAN #2] -- Saran Klinis Dinamis di Mesin Logika RF
  ============================================================
  File     : src/App.tsx (fungsi getDetailedAdvice + AI panel)
  Status   : DIPERBARUI

  Masalah Lama:
    - Judul hanya: "Diagnosis: Normal/Peringatan/Bahaya"
    - Saran teks statis/hardcoded, tidak mempertimbangkan
      parameter sensor mana yang menjadi penyebab kondisi.

  Solusi Baru:
    Fungsi getDetailedAdvice(status, rr, bpm, temp) membaca
    nilai AKTUAL sensor untuk menentukan saran klinis spesifik.

  Judul Rekomendasi RF:
    Normal      -> "Semua Parameter Normal"
    Peringatan  -> "Tanda Vital Perlu Diperhatikan"
    Bahaya      -> "Kondisi Kritis - Tindakan Segera"

  Logika Saran Klinis [BAHAYA] (prioritas: RR > BPM > Suhu):
    RR >= 32    : Takipnea -> posisi semi-Fowler, oksigen masker,
                              hubungi dokter, siapkan nebulizer
    RR <= 8     : Bradipnea/Apnea -> ventilasi bag-mask,
                                     panggil tim resusitasi darurat
    BPM >= 141  : Takikardia berat -> pasang EKG, evaluasi aritmia,
                                      siapkan defibrilator
    BPM <= 39   : Bradikardia berat -> pertimbangan atropin/
                                       alat pacu jantung
    Suhu >= 38.5: Demam tinggi -> antipiretik, kompres,
                                  pantau input/output tiap 30 menit
    Suhu <= 32.9: Hipotermia berat -> selimut hangat, cairan hangat,
                                      pantau tanda vital tiap 10 menit

  Logika Saran Klinis [PERINGATAN] (prioritas: RR > BPM > Suhu):
    RR >= 24    : Laju napas meningkat -> posisi Fowler, latihan
                                          napas dalam 4-hitungan
    BPM >= 96   : Detak jantung naik -> cek aktivitas/stres,
                                         berbaring rileks, ukur ulang
    Suhu >= 35.6: Suhu naik ringan -> pantau tren, hidrasi 2L/hari

  Logika Saran Klinis [NORMAL]:
    -> Pemantauan rutin setiap 2 jam, istirahat cukup,
       sirkulasi udara yang baik.
